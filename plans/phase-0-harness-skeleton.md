# Phase 0 — Harness Skeleton

**Goal (blueprint §13):** the machine runs end-to-end on one question. A minimal LangGraph — one research node → one synthesizer — over a single 10-K, with Langfuse tracing wired in from the first commit, on a repo scaffolded around the harness layers of blueprint §3.

## Context (read this if starting cold)

The project is a multi-agent system that answers analyst questions over SEC filings and verifies every claim against a source (see `../financial-intelligence-engine-blueprint.md`). This phase builds none of the verification yet — it builds the *harness*: the module structure, typed state, model routing, observability, and a trivially simple graph proving the plumbing works. Everything later phases add is a new node or tool inside this skeleton; nothing should require restructuring it.

Corpus for this phase: **one document — Apple's latest 10-K** — fetched from SEC EDGAR. Retrieval is deliberately naive (in-memory BM25 over parsed sections); production retrieval arrives in Phase 3.

## Prerequisites

- macOS dev machine with Docker Desktop (for Langfuse) and `uv` installed.
- API keys in a local `.env`: `ANTHROPIC_API_KEY`, `OPENROUTER_API_KEY` (Langfuse keys are generated by its local UI after first boot).

## Deliverables

1. **Repo scaffold** exactly as §5 of `00-overview.md` (only the modules this phase needs get real code; others get the package + a docstring stating which phase fills them).
   - `pyproject.toml` via `uv init`; deps: `langgraph`, `langchain-anthropic`, `langchain-openai` (OpenRouter path only), `langfuse`, `edgartools`, `rank-bm25`, `pydantic`, `pydantic-settings`, `typer` (CLI). Dev deps: `ruff`, `mypy`, `pytest`, `pytest-asyncio`.
   - `ruff` + `mypy --strict` configured in `pyproject.toml`; a `justfile` or `Makefile` with `lint`, `typecheck`, `test`, `run` targets.

2. **Langfuse, self-hosted locally** (`docker-compose.dev.yml`).
   - Use Langfuse's official self-host compose (it bundles Postgres, ClickHouse, Redis, MinIO — heavy but that *is* the self-host story). Vendor their compose file in and pin image versions.
   - `src/fie/observability/`: a single `get_langfuse_handler()` used by the graph entrypoint (Langfuse's LangChain/LangGraph callback handler), plus helpers to tag traces with `run_id`, model role, and phase. **Rule from the blueprint: every node, tool call, token count, and cost must appear in the trace.** No other module imports Langfuse directly.

3. **Typed state** (`src/fie/state/`). Pydantic models used inside a LangGraph state schema. Define now (later phases extend, not replace):
   - `EvidenceChunk`: `chunk_id, doc_id, ticker, form_type, section, text, score, metadata` (metadata carries `accession_no`, `filing_date` — this is the citation trail, blueprint §5).
   - `EngineState` (the graph state): `question`, `evidence: list[EvidenceChunk]`, `draft_answer`, `run_budget` (placeholder fields for tokens/cost, real enforcement in Phase 1). Fields already named in the blueprint but not yet used (`sub_questions`, `claims`, `verdicts`, `rejection_feedback`) are declared with empty defaults so the schema is stable across phases.

4. **Model router** (`src/fie/llm/`). A `get_model(role)` factory returning a configured chat model per role, per the routing table in `00-overview.md` §4: `synthesis` → `claude-opus-4-8` via `langchain-anthropic` (adaptive thinking on); mechanical roles → cheap OpenRouter model via the OpenAI-compatible client pointed at OpenRouter's base URL. Model IDs come from `config.py`, never hardcoded at call sites. Never route an Anthropic model through the OpenRouter/OpenAI-compatible path.

5. **Document source + naive retrieval** (`src/fie/tools/`).
   - `fetch_filing(ticker, form_type)` using `edgartools` (set the SEC-required identity/user-agent from config); cache the raw filing under a gitignored `data/` dir so reruns don't hit EDGAR.
   - Parse the 10-K into sections/items via `edgartools`' structured accessors; build `EvidenceChunk`s (one per section or per ~1k-token slice of a section, carrying section metadata).
   - `retrieve(query, k)` — in-memory BM25 (`rank-bm25`) over the chunks. This is a placeholder with the *same interface* Phase 3's Qdrant retrieval will implement; define that interface as a small protocol/ABC now.

6. **The minimal graph** (`src/fie/graph/`). Two nodes: `research` (calls `retrieve`, packs top-k into state) → `synthesize` (calls the `synthesis` model with question + evidence, instructed to cite chunk ids inline like `[c3]`). Context packing (which chunks, how truncated) lives in `src/fie/context/`, not inside the node — the separation is the point (blueprint §3 instruction).

7. **CLI**: `uv run fie ask "What were Apple's main revenue segments last fiscal year?"` → prints the answer with citations and the Langfuse trace URL.

8. **Tests**: unit tests for chunking (a section becomes chunks with correct metadata), the retrieval interface, and the router (roles map to configured IDs); one integration test running the graph end-to-end with mocked LLM responses (no network in tests).

## Explicitly out of scope

Verification, decomposition, fan-out, Qdrant, embeddings, eval metrics, FastAPI, deployment. Do not add them "while at it" — each is a later phase with its own gate.

## Exit gate

- `fie ask` answers one real question over the Apple 10-K end-to-end.
- The Langfuse trace shows: both nodes as spans, the retrieval tool call with its inputs/outputs, token counts and cost per LLM call, total latency.
- `ruff` / `mypy --strict` / `pytest` all green.
- `docs/decisions/` contains ADRs for: model routing defaults, edgartools as the EDGAR client, the retrieval interface.
